# 隔离与恢复手册

FileGuard 的清理是可恢复隔离。默认只生成计划（dry-run），不会修改文件。应用前应阅读计划、逐项确认保留副本、容量和目标路径。隔离通常只把文件移到同一卷的受控目录，不会立刻释放空间；永久清除是独立动作且必须二次确认。

## 推荐流程

1. 扫描受控测试或业务根目录，等待任务成功或明确部分失败。
2. 查看重复组，确认每组有至少一个可读的 keeper。优先目录、时间及显式 keep 路径都只产生候选，核心会再次验证。
3. 创建计划并保存其唯一 ID。计划有版本、扫描来源、创建/过期时间、逐项候选和 keeper。
4. 预览计划。过期、越界、链接、身份变化、摘要变化或 keeper 丢失时不要强行执行；重新扫描并创建新计划。
5. 使用显式确认应用计划。CLI 无人值守必须同时传计划 ID 和确认参数；缺少任一项不会修改文件。
6. 查看操作历史中的 `planned`、`started`、`copied`、`completed`、`skipped` 或 `failed` 与安全检查结果。
7. 需要时按单个操作恢复。恢复发生同名目标时会拒绝，绝不静默覆盖；手工移动冲突文件后再重试。首版只恢复到记录的原路径，不提供改名恢复参数，也不自动重新创建已丢失的祖先目录。
8. 只有确认备份和合规要求后，单独执行永久清除命令并再次确认。

## 故障与中断

同卷移动使用句柄 rename。跨卷操作先以独占新建方式复制到隔离目标，流式校验内容，持久化 `Copied` 状态及目标身份，再删除源文件句柄；任一环节失败保留源文件及失败记录。崩溃后运行 `quarantine recover` 先预览未完成日志，再运行 `quarantine recover --confirm` 对照源/目标状态和摘要、身份：无法证明完整性的对象标记 `NeedsReview`，必须人工检查；不能仅凭“目标存在”标记成功。

跨卷复制中断时，如果原文件身份和完整摘要仍匹配，且隔离对象身份匹配、其内容逐字节等于完整源文件的前缀，恢复可移除自身不完整副本并把操作重置为 Planned，供再次显式应用。跨卷恢复中断且两份副本都存在时，同样需要完整隔离源、目标身份及字节前缀验证通过后才移除部分恢复副本。任何身份无法确认或副本包含不同内容都保留对象并标记 NeedsReview；崩溃后同一文件身份上的内容修改不会被静默删除。

Web 的“核对中断操作”会先列出候选记录并要求输入 RECOVER 确认。此动作可能撤销已验证的部分复制对象，应先阅读预览和每项状态。

同卷 rename 保留原文件元数据。跨卷实现保证未命名内容流和最后修改时间，目标 ACL 按新建目录继承；不保证原创建时间、访问时间、所有者、自定义 ACL、扩展属性或稀疏/压缩布局。带命名数据流的文件保守拒绝，不会静默丢失额外流。需要完整元数据归档时，应使用独立备份工具并保留备份。

进程取消会停止新工作、释放文件句柄和数据库连接并持久化逐项状态。任务重启不能把运行中任务伪装成成功。首版没有检查点续扫，原扫描进程确认已退出时会标记 `Interrupted` 并说明不可原地恢复；使用 `scans show` 查看原参数，重新运行 `scan` 获得新任务 ID。

容量不足、权限变化、文件被占用或路径身份变化都可能造成逐项跳过。不要删除隔离区的元数据来“清理”失败记录；先导出或恢复可读对象，再按记录处理。

## 保护边界

首版默认拒绝 symlink、junction 和其他 reparse point，不跟随链接进入隔离区。清理前核心会重新打开候选和 keeper，复核最终路径、祖先链接、OS 身份、大小及 SHA-256。平台无法保证 TOCTOU 安全时会保守拒绝修改。Windows 是首选的可修改平台；其他平台的扫描/清单能力和文件身份保证见 [security.md](security.md)。
