# 架构与技术决策

FileGuard 使用 .NET 10 / C# 14。CLI 与中文 Blazor Web 是同一核心应用服务的两个入口；扫描、摘要、计划安全核验及隔离规则只在核心实现。Web 操作的是服务进程可访问的文件系统，浏览器客户端磁盘不会自动成为扫描目标。

## 项目边界

| 项目 | 职责 |
| --- | --- |
| `src/FileGuard.Core` | 配置与模型、路径策略、OS 文件身份、扫描流水线、SHA-256、重复检测、公开清单、SQLite、清理计划、隔离与恢复。 |
| `src/FileGuard.Cli` | 参数与配置优先级、帮助、协议输出、退出码、取消信号、调用 Core、启动 Web。 |
| `src/FileGuard.Web` | 认证会话、CSRF、Host/Origin 校验、允许根目录管理、Blazor 交互及 Core 服务调用。 |
| `tests/` | 专用临时数据上的核心、入口、安全、并发、恢复与平台验证。 |
| `scripts/` | 本地构建、启动、发布、验收与可重复基准。 |

核心服务不依赖浏览器或终端。API 和 CLI 必须使用同一组计划模型与核心状态机，不能在前端重新判断文件是否可清理。

## 扫描流水线

```mermaid
flowchart LR
  A[允许根目录与过滤规则] --> B[异步目录枚举]
  B --> C[有界文件 Channel]
  C --> D[固定数量读取/哈希工作者]
  D --> E[有界结果 Channel]
  E --> F[SQLite 持久化]
  F --> G[重复组与清单]
```

队列容量和工作者数量都有明确上限。每个文件不创建独立的无限生命周期 Task。读取使用固定大小流式缓冲；单个大文件不载入内存。目录项在入队前应用过滤和链接规则。遍历、读取字节、错误及当前状态独立计数，取消令牌贯穿枚举、队列和 IO。

记录文件元数据和可靠 OS 身份，读取完成后再次核验。若身份、长度、修改信息变化，结果标记为不稳定，不把旧摘要作为确认内容。扫描不是整棵目录树的原子快照，验证结果只描述文件在被读取时的观测。

重复检测先按大小找候选，再以完整 SHA-256 分组。硬链接依据物理身份合并计量。清单创建需要覆盖所有符合规则的文件，因此可能需要对非重复候选也计算摘要；此成本在基准中与候选数分别报告。

## 数据与任务生命周期

SQLite 保存允许根目录、扫描任务、文件索引、清理计划、操作日志和数据库 schema 版本。各工作单元使用独立连接/事务，避免跨工作者共享未同步的数据库会话。数据库配置、迁移和当前版本以实际 Core 实现为准；升级遇到未知更高版本应安全拒绝。

扫描状态至少区分待执行、运行中、成功、部分失败、取消、失败及中断。进程重新启动时，不能把之前运行中的任务判为成功。首版可以把中断扫描明确标记为不可续传，提供从相同参数重新扫描的操作；不得以“继续”冒充从检查点恢复。

隔离操作采用持久化状态机：计划先落盘，执行开始前记录 started，每个实际文件操作及安全检查均记录日志，操作成功且完成必要校验后才记录 completed。失败保留恢复元数据和原因。重启通过日志与实际源/目标状态对照处理未完成操作，不能只根据某个文件存在便假定成功。

CLI 与 Web 可以连接同一个数据库。修改文件的互斥必须通过数据库级或操作系统跨进程机制实现。进程内 `lock` 只可用于局部同步，不能当成跨进程安全证明。互斥覆盖重复计划和候选文件，以避免两个执行者同时操作同一文件。

## 文件操作与 TOCTOU 边界

路径先标准化，再按真实文件系统语义验证根边界。清单路径只允许规范相对路径。根、祖先目录、候选、保留项和隔离目标的链接状态及最终身份都属于安全核验对象。默认拒绝 symlink、junction 和其他 reparse point；首版不提供跟随模式。

扫描结果只用于形成可审查计划。执行时重新打开候选及保留项，复核身份、大小、摘要并逐字节比较。计划过期、候选变化、保留副本丢失、链接替换或任何身份不确定都应拒绝或逐项跳过并解释原因。

平台必须证明其最终操作路径与已验证身份保持一致。仅在字符串路径上多检查一次仍不能消除竞态。如果当前平台不能提供所需保证，核心应保守拒绝相应修改，界面必须展示限制；扫描和清单仍可提供读取能力。平台验证状态记录在 [security.md](security.md) 与 [test-report.md](test-report.md)。

同卷隔离优先 rename；跨卷隔离需要先复制至隔离区的临时对象，完整校验，持久化提交阶段，然后删除原对象。崩溃可能留下两份副本，恢复逻辑优先保留数据。恢复禁止静默覆盖。永久清除独立执行并再次确认。

## 空间统计

逻辑大小是文件内容字节数。硬链接共享同一个物理对象；稀疏、压缩、去重、快照、写时复制和存储分配单位进一步使逻辑大小与物理占用不同。不能从 `Length` 推导确定的物理回收量。估算未知时返回未知，并解释原因。

隔离是可恢复移动，通常不会释放同卷空间；跨卷隔离消耗目标卷空间。只有之后独立永久清除才可能释放物理空间，且快照或其他硬链接仍可能保留块。因此预计空间、已移动逻辑字节和实际回收必须区分。

## Web 安全

默认监听 loopback，使用受保护会话。所有变更请求执行认证、CSRF 和 Host/Origin 验证。根目录允许列表由服务端管理；扫描 HTTP 参数只能引用已授权根或其受控范围。默认不开放远程匿名访问、不提供任意文件下载、不上传被扫描文件内容。

普通应用日志使用任务 ID、相对路径或错误类别，避免泄露完整本地绝对路径。用户主动打开本地诊断模式后，诊断记录仍只保留在本机且不得提交到仓库。

## CLI 与 Web 配置转发

`fileguard serve` 是受控的 Web 进程启动器。它验证 URL 必须是 loopback HTTP，然后转发 `--config`、数据目录、允许根、隔离目录、并发、Channel 容量、IO 预算和诊断开关到 Web；不会转发任意未知参数。默认寻找与 CLI 相邻的 Web 可执行文件，也接受显式 `--web-path`。Web startup token 写入 `<data>/web-private/startup-token.txt`，CLI 不读取、不打印 token。服务输出流直接转发到调用端 stderr/stdout，Ctrl+C 先等待有序退出再在 5 秒后终止进程树。

## 验收与交付策略

每个里程碑先构建、执行适用测试与手工验证，再审查 diff 和暂存内容，按提交规范创建本地提交并记录远程推送结果。测试数据、SQLite 文件、日志、发布产物与凭据不得加入源码提交。所有异常路径均使用生成数据验证。需求覆盖按 [requirements.md](requirements.md) 的编号记录，未验证平台能力不得描述为已保证。
