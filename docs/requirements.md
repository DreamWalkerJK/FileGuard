# FileGuard 需求与验收矩阵

本文件把用户目标拆分成可验证要求。实现与验收以真实文件操作、当前代码和实际命令输出为依据；文档、演示数据或测试名称本身不能证明功能完成。所有破坏性验证必须使用项目忽略的专用临时目录。详细测试结果和未验证能力记录在 [test-report.md](test-report.md)，交付和 Git 证据记录在 [progress.md](progress.md)。

## 最终端到端门槛

CLI 与 Web **各自**必须在生成的专用测试树完成以下 11 步；不能仅以共用 Core 的单元测试代替入口验收。

1. 扫描目录。
2. 查看重复组。
3. 按保留规则生成计划。
4. 预览每个候选及保留项。
5. 显式执行并将候选移入隔离区。
6. 查看逐项操作记录。
7. 恢复并逐字节核验内容。
8. 创建完整性清单。
9. 修改生成的测试文件。
10. 验证清单并展示变化；比较两份清单。
11. 对过期计划或已变化文件得到可解释的安全拒绝或跳过结果。

任何未通过门槛、未完成交付或缺乏充分证据的要求必须保留为未完成，不能在最终报告中声明整体完成。
